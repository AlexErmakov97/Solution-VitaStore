- как продажи и остатки магазина попадают в SAP — вероятно, обратным ночным файлом;
- как акции из Promo Engine доходят до кассы и откуда Smart Fulfillment берёт остатки для Click & Collect;

  TCO.

## 2. Целевая архитектура

### 2.1. Принципы

1. **В магазине нет серверов.** Остаются планшет, фискальный регистратор, банковский терминал и роутер с резервным
   каналом.
2. **Тонкий, но офлайн-способный клиент.** Касса не хранит бизнес-данные как источник истины, но держит локальный кеш и
   очередь операций, чтобы продавать без интернета.
3. **Касса не знает модели оборудования.** Всё железо — за слоем абстракции HAL с единым API.
4. **Обмен событиями вместо ночных файлов.** Цены, ассортимент и акции доходят до касс за минуты, продажи и остатки — до
   SAP и Smart Fulfillment.

### 2.2. Компоненты

| Где     | Компонент                                                                   | Модель (из задания 1) | Назначение                                                                              |
|:--------|:----------------------------------------------------------------------------|:----------------------|:----------------------------------------------------------------------------------------|
| Планшет | Cloud POS-клиент (Web POS / PWA или лёгкое приложение)                      | SaaS                  | интерфейс кассы, расчёт чека по локальному кешу                                         |
| Планшет | Локальное хранилище (SQLite / IndexedDB, шифрование)                        | часть клиента         | кеш справочников, цен, акций, балансов лояльности; outbox — очередь операций            |
| Планшет | **HAL Agent**                                                               | Build                 | единый API к оборудованию, плагины ККТ и терминалов                                     |
| Магазин | ККТ с фискальным накопителем, банковский терминал, роутер с LTE             | on-prem               | устройства, которые по закону или физически должны быть на месте                        |
| Облако  | API Gateway                                                                 | управляемый сервис    | вход для планшетов: mTLS, авторизация устройств                                         |

## 3. Переход от толстого клиента к cloud-native

Переход идёт **по магазинам** (Strangler Fig на уровне сети): старая и новая касса какое-то время живут параллельно, а
сервер магазина выводится только после стабильной работы новой.

| Этап                                | Срок        | Что делаем                                                                                                                                                                                        | Результат                                                             |
|:------------------------------------|:------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------------------------------------|
| 0. Основа                           | месяцы 1–3  | выбор Cloud POS по критериям (офлайн-режим, 54-ФЗ, открытый API, данные в РФ); интеграционная шина вместо FTP; MVP HAL Agent и Payment Gateway с плагинами для самых частых ККТ и терминалов; MDM | всё готово для пилота; SAP публикует цены событиями                   |
| 1. Пилот                            | месяц 4     | 3–5 магазинов разных типов, включая купленный; старый сервер остаётся резервом на 2 недели                                                                                                        | проверены офлайн-режим, HAL, синхронизация; замерены реальные затраты |
| 2. Новые магазины сразу в облаке    | с месяца 5  | все купленные магазины подключаются без сервера: планшеты + плагины HAL + онбординг из задания 2                                                                                                  | подключение за 5 дней, без выезда бригады                             |
| 3. Волны миграции существующей сети | месяцы 5–11 | по 50–80 магазинов в месяц; сначала те, где сервер старый или пора продлевать лицензии                                                                                                            | серверы и лицензии выводятся                                          |
| 4. Вывод легаси                     | месяц 12    | отключение FTP-обмена, толстого клиента, поддержки драйверов                                                                                                                                      | Store Ops поддерживает один стек                                      |

**Критерий вывода сервера в магазине:** две недели без инцидентов на новой кассе, все операции из outbox
синхронизированы, сверка выручки с эквайером и ОФД сходится.

## 4. Слой абстракции оборудования: HAL и Payment Gateway

### 4.1. Почему из двух частей

Облачное приложение не может обратиться к USB или COM-порту устройства в магазине. Поэтому абстракция разделена:

- **HAL Agent на планшете** — работает рядом с устройствами и говорит на их протоколах;
- **Payment Gateway в облаке** — управляет: какие устройства стоят в магазине, какие плагины им нужны, через какого
  эквайера идёт оплата; хранит журнал и сверяет операции.

Касса общается только с HAL Agent через единый локальный API (WebSocket на localhost) и не знает, какой терминал или
регистратор подключён.

### 4.2. Единый API для кассы

| Операция                          | Что делает                                 | Работает офлайн                        |
|:----------------------------------|:-------------------------------------------|:---------------------------------------|
| `printReceipt`                    | фискализирует и печатает чек на любой ККТ  | да                                     |
| `pay` / `refund`                  | оплата и возврат картой на любом терминале | если у терминала есть свой канал связи |
| `openDrawer`, `cashIn`, `cashOut` | денежный ящик, внесение и изъятие          | да                                     |
| `xReport`, `closeShift`           | отчёты и закрытие смены                    | да                                     |
| `deviceStatus`                    | состояние устройств для мониторинга        | да                                     |

### 4.3. Плагины

- **Плагин ККТ** оборачивает драйвер производителя (АТОЛ, Штрих-М и др.) в единый интерфейс.
- **Плагин терминала** оборачивает протокол или SDK эквайера: Сбер (ARCUS-2 / UPOS), Альфа, Ingenico, Verifone.
- Плагины версионируются в реестре Payment Gateway и доставляются на планшеты через MDM. Payment Gateway знает, какие
  устройства стоят в каждом магазине, и назначает нужные плагины автоматически.

**Сценарий INC-8415** (терминалы Сбера в купленной сети): сейчас — 3 недели на драйвер и пересборку кассы. В целевой
архитектуре плагин ARCUS-2 пишется один раз, после этого любой магазин с таким терминалом подключается настройкой в
реестре, а касса не меняется.

### 4.4. Безопасность и требования закона

- Данные карт не покидают терминал (PCI DSS): HAL и облако получают только результат операции, маскированный номер и
  идентификатор транзакции.
- Фискализация — только на ККТ с фискальным накопителем (54-ФЗ); облачная касса не заменяет регистратор.
- HAL Agent принимает команды только от кассового приложения на этом же планшете; планшет управляется через MDM,
  локальные данные зашифрованы.

## 5. Работа магазина при обрыве связи (Offline-mode strategy)

### 5.1. Что работает без интернета

| Функция                                | Офлайн                                                       | Как                                                                                                                    |
|:---------------------------------------|:-------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------------------|
| Продажа за наличные с фискальным чеком | **да, без ограничений**                                      | цены и акции из кеша; HAL печатает чек на ККТ; фискальный документ копится в ФН до восстановления связи                |
| Продажа по карте                       | да, если у терминала есть свой канал (SIM / отдельная линия) | при полном отсутствии связи — только наличные                                                                          |
| Начисление баллов                      | да                                                           | операция в outbox, начисляется после синхронизации                                                                     |
| Списание баллов                        | ограниченно                                                  | в пределах кешированного баланса и лимита на чек (например, до 500 баллов); без связи дольше 24 ч списание отключается |
| Возвраты                               | да, по чекам этого магазина                                  | чек ищется в локальном кеше                                                                                            |
| Выдача заказов Click & Collect         | да, по заранее загруженному списку                           | факт выдачи — в outbox                                                                                                 |
| Изменение цен и акций из HQ            | нет                                                          | применяются после восстановления связи                                                                                 |

### 5.2. Как снижается число офлайн-эпизодов

- **Резервный канал LTE** на роутере магазина: обрыв кабеля провайдера (как в INC-8402) не приводит к офлайну.
- Кеш на планшете обновляется постоянно и всегда содержит полный справочник и цены магазина (около 10 000 позиций —
  единицы мегабайт).

### 5.3. Ограничения длительного офлайна

- ККТ блокирует пробитие чеков, если фискальные документы не передаются в ОФД дольше 30 дней. Мониторинг поднимает алерт
  уже через несколько часов офлайна.
- Через 24 часа без связи касса показывает предупреждение, а списание баллов отключается.

## 6. Механизм синхронизации при восстановлении связи

Каждая операция на кассе — продажа, возврат, начисление или списание баллов, внесение или изъятие наличных, выдача
заказа — сначала записывается в локальную очередь (outbox) на планшете, и только потом отправляется в облако. Запись
получает уникальный идентификатор (UUID), порядковый номер на устройстве и время создания. Онлайн очередь отправляется
сразу и почти всегда пуста. Офлайн записи накапливаются, а касса продолжает работать по кешу. Когда связь появляется,
клиент отправляет очередь в Sync API строго в порядке номеров, пакетами, и удаляет запись только после подтверждения
сервера. Если связь снова оборвалась посреди отправки, неподтверждённые записи будут отправлены повторно.

Sync API обрабатывает каждую запись идемпотентно: повторная запись с тем же UUID не создаёт второй чек и не списывает
баллы дважды, а возвращает прежнее подтверждение. Конфликтов «кто прав» почти не возникает, потому что продажи —
неизменяемые факты: чек, пробитый офлайн по цене из кеша, остаётся проданным по этой цене, даже если в облаке цена уже
изменилась. Производные данные пересчитываются в облаке: остатки уменьшаются на проданное (допускается временный
отрицательный остаток, его разбирает товарный учёт), баллы начисляются и списываются программой лояльности. Если
офлайн-списание баллов оказалось больше реального баланса, разница ограничена лимитом на чек и учитывается как
допустимый риск. Затем подтверждённые продажи уходят в интеграционную шину — в SAP, Smart Fulfillment и аналитику.
Фискальные документы касса не пересылает: их сама дозагружает ККТ из фискального накопителя в ОФД.

После отправки очереди касса забирает изменения справочников: цены, ассортимент, правила акций, статусы заказов Click &
Collect. Каждый справочник имеет номер версии; клиент сообщает последнюю известную версию и получает только дельту, а
при большом разрыве — полный снимок своего магазина. Справочники в облаке главнее: локальные копии только заменяются, но
не правятся на кассе. Пока синхронизация не завершена, касса продолжает продавать. Мониторинг видит длину очереди и
время последней синхронизации каждой кассы: алерт поднимается, если очередь не уменьшается или касса долго не выходит на
связь.

## 7. Как архитектура решает цели бизнеса

| Цель                                | Как достигается                                                                                                                                      |
|:------------------------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------|
| TCO магазина −40%                   | нет локальных серверов, лицензий Windows Server и SQL, их администрирования и выездов на замену железа (INC-8433); касса — подписка SaaS на планшете |
| Подключение магазина за 5 дней      | нечего настраивать на месте: планшеты настраиваются через MDM, плагины HAL назначаются из реестра, данные готовит платформа онбординга (задание 2)   |
| Любые терминалы без доработки кассы | HAL Agent + Payment Gateway: новый протокол — новый плагин, касса не меняется (INC-8415)                                                             |
| Работа без интернета                | офлайн-кеш и outbox на планшете, ККТ с ФН, резервный канал LTE, лимиты на лояльность (INC-8402)                                                      |

| Риск                                                                    | Мера                                                                                                       |
|:------------------------------------------------------------------------|:-----------------------------------------------------------------------------------------------------------|
| Выбранный Cloud POS не поддерживает нужный офлайн-режим или внешний HAL | офлайн-сценарии и открытый API — обязательные критерии выбора, проверка на пилоте                          |

| Планшет — единственная касса в маленьком магазине                       | второй планшет в резерве или смартфон с тем же приложением; HAL работает с ККТ по Bluetooth или USB        |
| Расхождение остатков после долгого офлайна                              | пересчёт в облаке, допуск отрицательного остатка, сверка при инвентаризации                                |
| Перерасход баллов в офлайне                                             | лимит на чек и отключение списания после 24 ч без связи                                                    |
